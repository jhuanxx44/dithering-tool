# 1-bit 配光与验证

配光决定效果好不好看。这是这个项目最容易翻车的地方，读完再动手。

## 核心原理

抖动只有「有墨 / 无墨」两级。**形体靠区域之间的密度差读出来，不是绝对亮度。**

一个网点要么着墨要么留白，中间灰度是靠「一片区域里有多少比例的网点着墨」表达的。所以能不能看出形体，取决于相邻区域的**密度是否拉得开**。

## 四条铁律

**① 排出三段密度差**

```
背景最亮（几乎不出网点）→ 地面次之（稀疏）→ 造型暗面最暗（密集）
```

内置场景实测：天空 0% 墨 → 地面 4.9% → 造型 26.4%。

**② 背景要给亮**（最反直觉的一条）

`shadow` 预设里墨点跟着**暗部**走。所以深色背景会整片长满网点，和主体糊在一起、轮廓被吞掉。

换成亮背景后留白干净、网点集中在造型暗面，才是铜版画那个味道。

**③ 不要压到中灰**

想着「压低对比避免过曝」很容易过头。整幅挤在中间调 → 满屏 50% 噪点 → 轮廓完全溶掉。

**④ 不要让亮部顶到 1.0**

顶满就是一整片实心，同样丢形体。而且造型亮面还要**低于**背景亮度，否则轮廓溶进背景。

内置场景的取值：造型 0.06–0.72，背景 0.94–0.99。造型亮面（0.72）明显低于背景（0.94），所以轮廓立得住。

## 一个反直觉的技巧

**轮廓边缘要压暗，不要提亮。**

常规渲染里边缘光（rim light）是提亮的。但在亮背景 + 1-bit 下，提亮边缘等于让轮廓溶进背景。改成压暗后，边缘会长出一圈密网点，在亮背景里勾出**实心的外轮廓线**——这才是版画感的来源。

内置场景的做法：`value -= 0.34 * Math.pow(1 - facing, 3)`。

## 怎么验证（不要只看截图）

肉眼看截图很容易漏掉「密度差不够」这种问题。用分区密度采样：

```js
// 在浏览器里对渲染结果分区统计墨点占比
const cv = fx.shadowRoot.querySelector('canvas');
const ctx = cv.getContext('2d');

function inkRatio(x0, y0, x1, y1) {
  const d = ctx.getImageData(x0, y0, x1 - x0, y1 - y0).data;
  let ink = 0, n = 0;
  for (let p = 0; p < d.length; p += 4) { n++; if (d[p] < 128) ink++; }
  return (ink / n * 100).toFixed(1) + '%';
}

const w = cv.width, h = cv.height;
console.log('背景', inkRatio(0, 0, w * 0.22, h * 0.18));
console.log('主体', inkRatio(w * 0.38, h * 0.30, w * 0.62, h * 0.52));
console.log('地面', inkRatio(0, h * 0.82, w, h));
```

健康的输出应该是三个明显不同的数字，且顺序为「背景 < 地面 < 主体」。

如果三个数字接近 → 密度差不够，形体读不出来。
如果主体接近 50% → 压到中灰了。
如果主体接近 0% 或 100% → 顶到极值了。

## 换造型 / 换模型后的自检清单

- [ ] 三段密度差拉开了（背景 < 地面 < 主体）
- [ ] 主体不在 50% 附近，也不在 0% / 100% 附近
- [ ] 多种造型互不相同（不要出现两种造型渲染结果一样）
- [ ] 全屏性能可接受（内置 3D `grid=4` 应在 ~11ms/帧 量级）

## 性能：包围球剔除

内置 3D 场景的性能关键是**两级剔除**：

1. 包围球先排掉打向天空和远处地面的视线——这占绝大多数
2. 地面的阴影步进只对包围球附近的点做

加上这两步后全屏 1280×800 从 25ms/帧 降到 11ms/帧（`grid=4`），墨点密度差在 0.2% 以内，是等价优化。

所以**新造型必须留在 `BOUND_R`（1.55）内**，否则会被剔除逻辑切掉。造型更大就同步调大这个常量，并重新测性能。
